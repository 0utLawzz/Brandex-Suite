# Brandex Suite — daily working guide

## 1. Register the client and case

Open **New Case / Case Registration**. Search for a repeat client first. For a new client, choose the series, client number, name/address, payment terms and Stage 1–4 rates. Series can be added. The default for every series is Monthly Billing / Credit.

`X-254-002` means series X, client 254, case 002. The case number is manual. A trademark number is separate: leave it blank before issue, then save its exact six digits. Leading zeros are preserved. Class is 1–45.

New applications start Registered, awaiting actual filing. Takeover Stage 2/3 cases start in Review; record their actual current event/date. Existing old records also require review rather than invented backfill.

## 2. Receive and allocate money

Open **Client Ledger**, select the client, then **ADD LINE** against the intended case/stage charge. Enter receiving total, date and verification name. Allocation may cover multiple cases/stages; leftover money stays as unallocated advance. It does not automatically pay another stage.

The case shows billed, allocated and outstanding separately. Monthly Billing allows work with visible debt. Explicit Advance terms require full allocation to the required stage before entry. There is no 60% rule. If the next stage charge is not yet issued, use **Prepare stage bill** on the case before receiving against it.

Stage rates are copied into each issued charge. Changing preset rates affects future charges only. A blank rate is **Rate needed**, never Paid. Old paid/pending ledger entries remain visible in historical case records but are excluded from new totals until reconciled.

Print a separate case receipt from receiving history. Edits preserve the receipt number and previous issued details. VOID retains history and corrects balances; it does not reverse an event that actually happened.

## 3. Proceed with actual case events

| Stage | Normal steps |
|---|---|
| Stage 1 | Registered → Filed → optional Examination (reply submitted) → Acknowledgement |
| Stage 2 | Assigned → Accepted; Hearing may intervene before Accepted |
| Stage 3 | Accepted → Published → Demand Note received; Objection is a separate follow-up path |
| Stage 4 | Actual ten-year fee submitted → Certificate at office → Dispatched / Delivered |

Stage 3 charge is issued at Accepted. Staff record actual events/dates; time never advances a case automatically. Calendar days include holidays. Filing waits up to 15 days; examination reply up to 7. Assignment is green through day 7, yellow 8–9, red from 10. Accepted by the 20th expects that month's journal on the 25th–28th; later acceptance waits for the next month. Publication waits two calendar months for Demand Note; actual ten-year fee submission starts the one-calendar-month certificate timer.

Flags focus work inside the app; they are not reminders. STOPPED pauses timing and preserves balances. TM-57 reactivation restores the previous step with its separate recorded charge. IPO restoration approval is a separate entry. Objection resolution and renewal automation are not invented by this release.

## 4. Associates, files and delivery

**Service Associates** are internal contacts/payees, not staff logins. Assign an agreed stage fee (default Rs.1,000); this is separate from client charges and becomes payable at assignment. Partial/weekly settlements allocate oldest unpaid fees first. Edit/VOID retains history. Existing paid assignment changes require reconciliation; no duplicate liability is created on retry.

Upload case files from the case workspace. X defaults to **1 ALL CLIENTS**, A to **2 CONSULTANTS**. Configured folders stay Restricted. Updating identity/TM renames the same bound case folder; files and folder ID are preserved. If a rename fails, retry from the case. App Viewer access alone does not grant access to private Google files; named Google access is also required.

Record certificate office receipt before dispatch. Courier details include company, tracking, destination, dates and delivery confirmation. An uploaded case receipt may be attached. Hand collection is also supported. A certificate may wait at the office without an automatic collection deadline.

Admin manages records. Viewer reads only. Audit history is available separately. Mail Merge remains a separate collapsible function in a case and is not the workflow/payment authority.
